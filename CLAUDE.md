# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Baby event-tracking PWA (React + .NET 10 + Postgres), open source AGPL-3.0. Spec: `docs/SPEC.md`. Plan/status: `docs/agents/PLAN.md`. Open review findings: `docs/agents/REVIEW.md`. Deploy: `docs/DEPLOY.md`. Navigation: `docs/agents/filemap.md` (update when adding/moving files).

## Stack
- Layout: application code under `code/` (`api`, `web`, `keycloak-theme`), the Playwright suite in `tests/e2e/`, the Python benchmark in `ml/`; docs, workflows, `docker-compose.yml` and the root `.env` stay at the root.
- `code/web/`: React 19 + TS + MUI, Vite SPA (no SSR), Dexie offline store.
- `code/api/`: .NET 10, layers Domain / Application / Infrastructure / Api; EF Core + Npgsql.
- `code/mobile/`: Capacitor 8 iOS/Android shell bundling `code/web/dist` (Vite mode `native`, `code/web/.env.native`); `npm --prefix code/mobile run build:web|sync|android|ios`; `@capacitor/*` pinned identically in web and mobile; web code reaches native only behind `isNativeApp()` (`code/web/src/platform`, lazy imports); see `docs/design/12-mobile-capacitor.md`.
- Commands: `dotnet build code/api/Lotties.sln`, `dotnet test code/api/Lotties.sln`, `npm --prefix code/web run dev|build|test|lint`.
- E2E (real Keycloak + DB, needs root `.env` incl. `E2E_*`): `npm --prefix tests/e2e install`, then `cd tests/e2e && npx playwright test`; see `docs/E2E.md`.

## Conventions
- Event model is generic (typed `Event` + JSONB payload); never add a table per event kind.
- Client generates event GUIDs; writes are idempotent upserts; deletes are soft.
- Auth is generic OIDC; never hardcode Auth0 specifics outside config.
- Persistence: Entity Framework Core (Npgsql), code-first migrations only; no raw SQL schema changes, no `EnsureCreated` outside the SQLite test host. Migrations are applied with `dotnet ef database update` (default) or, opt-in, at API startup with `DB_AUTO_MIGRATE=true` (migrator role, advisory lock); see docs/DEPLOY.md "Applying migrations".
- Predictions are pure Domain functions, no I/O.
- All AI-produced docs, plans, specs, reports and graphs go in `docs/` (graphify writes to `docs/graphify`, set via `.claude/settings.json`). Only CLAUDE.md, README, LICENSE, CONTRIBUTING stay at root.
- UI text: every user-visible string goes through i18n `t()` (en + pt-BR catalogs in code/web/src/i18n/locales); dates/numbers via Intl helpers; see docs/DESIGN.md section 9. Add UI strings to the feature's own file under `locales/<lang>/` (`locales/en/<feature>.json` and `locales/pt-BR/<feature>.json`).
- Parallel work: one git worktree per agent (`scripts/worktree-new.sh`, `worktree-integrate.sh`, `worktree-remove.sh`), integrated and deployed one feature at a time from the main clone; see `docs/PROCESS.md`.
- In a worktree never run `npm install`/`npm ci` or change dependencies: its node_modules are junctions to the main clone's.
- Use skills `develop:dotnet8` (api) and `refactor:react` (web).
- Subagents: Opus plans/orchestrates, Sonnet medium-hard, Haiku simple, never Fable.
- Container runtime is Podman inside WSL (archlinux distro), not Docker: run `wsl -- podman ...` or `podman-compose`. The WSL host runs the user's OTHER containers (traefik on :80, databases, etc.): never stop, remove or prune anything not named `br-*`; use only your own names and high ports. Rootful bridge networks fail there (nftables), use `--network host`.
- Secrets live only in the gitignored root `.env` (never read, print or commit it); the API reads `DB_*`, `AUTH_*`, `CORS_ALLOWED_ORIGINS` from env. No Docker/nginx on the dev machine: compose/Dockerfile/nginx changes can only be reviewed by eye.
- Sync contract: server `updatedAt` is the delta cursor; conflicts compare client `updatedAt` against stored `ClientUpdatedAt` (see SPEC "Events sync contract"). Never compare client clock with server `updatedAt`.
- Roles Owner > Parent > Caregiver > Viewer (SPEC "Roles and permissions"): a new API route needs a row in `EndpointRoleMatrixTests` (the test fails otherwise); web gates go through `baby/permissions.ts`.
- Account deletion: a new table or column that points at a baby or a user needs a rule in `AccountErasureTests.Rules`, an erasure step in `EfAccountDataEraser` and a row in that test's fixture (the test fails otherwise).
- Doctor role (docs/design/16-doctor-access.md): outside the Owner > Parent > Caregiver > Viewer order; reads, writes only her notes and consultation measurements, never gets reminders. Note visibility is filtered in the server query of every read: a private note never reaches another member.
- Web local data is per account (Dexie DB named from issuer+sub); logout/leave must warn about unsynced outbox and clear it. Server-provided keys (icons, field keys) go through `util/ownProperty.ts`.
- API tests run on SQLite (no Docker/Postgres): Postgres-only behavior (jsonb, xmin) is verified by the model/snapshot tests only. EF migrations are generated with `dotnet ef migrations add` (local tool manifest in code/api); no SQL script is checked in (generate one on demand with `dotnet ef migrations script --idempotent`, never commit it).
- Vaccine schedule: one source of truth `code/api/data/vaccine-schedule.br.json` (embedded in Lotties.Application, validated at startup, served with an ETag); the status engine exists in C# and TS with shared vectors (`code/web/src/vaccines/vaccineStatusVectors.json`); facts only, never advice (docs/design/18-vaccines.md section 8 for yearly updates).
- Age norms: one data file `code/api/data/age-norms.json` (embedded, validated at startup, `GET /age-norms` with an ETag, cached by the web); lookup in C# `AgeNormSet.PriorFor` and TS `priorFor` with shared vectors (`code/web/src/ageNorms/ageNormsVectors.json`); facts only, priors only: a `needsReview` or `confidence: low` norm is never used as a default, the app never calls a baby normal or abnormal, and every wired default is listed in docs/design/28-age-norms.md "Wired".
- A Doctor reads only the sections the Owner shares with her (scopes, enforced by the `BabyScope:*` policies; members, appointments and care providers are `BabyReadFamily`; a field of one section inside another's answer goes through `Domain/Babies/SectionView`): every new baby route needs a role and a scope decision in `EndpointRoleMatrixTests`; her patients never enter the parents' shell or the full sync, she works in `/doctor` (docs/design/19-doctor-dashboard.md).
- Real Napper exports contain a child's data: never commit them (`docs/samples/` is gitignored); tests use synthetic fixtures.
- Backup file (docs/design/24-export-import.md): `lotties-backup` JSON, one per baby, built (`IBackupExportService.WriteAsync`) and imported on the server through the normal application services in one rolled-back/committed transaction (so every validator and the sync contract apply); Owner/Parent only; the file never holds an account id, member, invite, doctor access or other people's private notes (authors are stand-ins); a merge never deletes or overwrites a newer copy; ids are derived from the target baby unless the file is merged into its own baby. A new kind of per-baby record joins the file in `BackupFile`, `BackupExportService` and `BackupApplier` (and its test in `Lotties.Api.Tests/Backups`); never export a user-level or secret field. Backup files are health data: never commit one.
- Voice assistants (docs/design/32-assistants.md, owner setup docs/ALEXA.md): adapters (Alexa now, MCP next) only authenticate, map intents to `Application/Assistants/IAssistantService` and render its language-neutral `AssistantResult`; writes go through the event service with UUID v5 ids from the request id; never a medication intent, free-text notes, advice, or logging of utterances/slots/tokens.
- Assistants (Alexa, the MCP server; docs/design/32-assistants.md): one command layer (`Application/Assistants`, language-neutral results); adapters only authenticate, check scopes, map and render, never add logic; never a medication tool, a dose, free text or advice; MCP tokens carry their own audience (never `AUTH_AUDIENCE`) and the `lotties.read`/`lotties.write` scopes; assistants never delete: they may only ask (`delete_requested_via`) and the person approves in the app; writes carry `via` (the adapter name, `updated_via` when it stops an entry another origin made); the cry answer always ends with the red flags and its scoring is shared with the web through `cryReasonsVectors.json`.
- Privacy policy (`/privacy`, text in `code/web/src/legal/privacy.<lang>.ts`, facts in `docs/design/33-privacy-audit.md`): any change that adds a data flow or a third party (a new kind of stored data, a service the app or API calls, a recipient, a log of personal data) updates the policy content in both languages, `legal/dataFlows.ts`, the audit and the policy version/date; never claim in it what the code does not do.
- Project board (`/api/v1/board`, docs/design/36-project-board.md): internal project tracking for the owner and the AI assistant, never baby data and never mixed with babies or families; access only by the Keycloak realm roles `lotties-board-reader`/`-writer`/`-admin` or hashed board API keys (`lbk_`, created by admins only, secret shown once); every board route needs a row in the board section of `EndpointRoleMatrixTests`.
- Privacy policy (`/privacy`, text in `code/web/src/legal/privacy.<lang>.ts`, facts in `docs/design/33-privacy-audit.md`): any change that adds a data flow or a third party (a new kind of stored data, a service the app or API calls, a recipient, a log of personal data) updates the policy content in both languages, `legal/dataFlows.ts`, the audit and the policy version/date; never claim in it what the code does not do. A device sensor (today only the cry monitor's microphone, web only, audio never stored or sent) is an `ON_DEVICE_FLOWS` entry.
- Official medicine list: ANVISA open data via the admin tool `code/api/tools/Lotties.CatalogImporter` (docs/design/13-anvisa-catalog.md); never infer an ingredient from a name or another product; never commit downloaded or derived data files (keep them in the tool's cache dir), never run it against the real DB from the agent. Curated list: `verify-curated` (same tool, reads the cache, docs/design/26-curated-verification.md) cross-checks it against ANVISA; its `anvisaCheck` is a machine check, never a pharmacist review (`reviewed` stays false until a person sets it); reports stay in the cache dir.
- Address lookup (docs/design/23-address-lookup.md): third parties (BrasilAPI, ViaCEP, OpenStreetMap Nominatim) are called only by the API proxy `/address/*`, only on the user's button press, never with anything about a baby or family; never log the typed text (HttpClient log category `AddressLookup` stays `None`); tests never reach the network (`NoNetworkHandler`); show "Data © OpenStreetMap contributors" wherever Nominatim results show.
- Units (docs/design/37-measurement-units.md; web side 37a): storage is metric forever (`amount_ml`, kg, cm, degrees C); the per-user setting `auto|metric|us` (`GET/PUT /me/unit-settings`, table `user_unit_settings`, never in the baby backup) only changes what people see, say and type; `auto` = locale region US/LR/MM is US customary; C# `Domain/Units` and TS `code/web/src/units` both pass `unitsVectors.json`; assistants speak the resolved system (`AssistantResult.Units`, bottle amounts may be said in ounces) while MCP structured values stay metric; never convert a medication dose.
