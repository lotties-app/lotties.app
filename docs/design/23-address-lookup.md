# Address lookup in the provider sheet: CEP and place search through our API (design, 2026-10-23)

Owner request: when adding or editing a doctor or clinic (docs/design/22-care-providers.md), help fill the address correctly with an address lookup API. Brazil first (CEP), a free-text place search for everything else. Privacy first, no API keys.

## 1. Decisions
- **User-triggered only.** A "Find address" button (or Enter in the box) sends one request. Never as you type, never on open, never on save. The box accepts a CEP (`01001-000`) or free text (`Rua Augusta, São Paulo`, a clinic name); 8 digits means CEP, anything else of 3 or more characters is a search.
- **Through our API, never from the browser.** The browser talks only to `GET /api/v1/address/lookup` and `/address/search`; the API calls the third parties. So the user's IP and browser fingerprint never reach BrasilAPI, ViaCEP or OpenStreetMap, the CSP `connect-src` stays unchanged, and offline behaviour is one rule (see 5).
- **Only the typed text leaves.** The upstream request carries the CEP digits or the search text and our `User-Agent`. Never a baby id, a name, a birth date, a family member or the signed-in user's identity. The routes are not baby-scoped, so the API handler does not even know which baby the sheet belongs to.
- **Single address text stays the model.** The provider keeps the one multi-line `address` the server already stores (400 characters). The lookup composes that text; nothing new is stored, no migration, no sync-contract change. Coordinates are returned by the API but the web ignores them: "Open in maps" keeps working from the text (docs/design/22 section 4). Storing latitude/longitude would need a nullable column pair, a migration and a contract bump for no visible gain today; if a map view is wanted later, add them then.
- **The manual field always works.** The lookup is an aid above the address field, not a gate. Offline, a failed lookup, a switched-off server: a message, and the address box is exactly as it was.
- **Who may call it.** Any signed-in user (`Access.SignedIn` in `EndpointRoleMatrixTests`). The owner's draft said "any signed-in user with write access to some baby"; that would need a membership query per call for a route that reveals nothing (the answers are public postal data) and holds no baby data, so the guard is authentication plus a per-user rate limit. The web only offers it in `ProviderSheet`, which only Owners and Parents can open. If abuse shows up, add a "member of any baby with Write" policy later; the matrix row is the place to record it.

## 2. Upstream sources (all free, no keys)
| Need | Source | Why |
| --- | --- | --- |
| CEP, first | **BrasilAPI** `GET https://brasilapi.com.br/api/cep/v2/<cep>` | Itself a multi-source aggregator (it falls back across several CEP providers), gives street, neighborhood, city, state and, when known, coordinates; 404 for an unknown CEP |
| CEP, fallback | **ViaCEP** `GET https://viacep.com.br/ws/<cep>/json/` | Long-lived and simple; unknown CEP is `200 {"erro": true}` |
| Free-text place | **OpenStreetMap Nominatim** `GET https://nominatim.openstreetmap.org/search?q=&format=jsonv2&addressdetails=1&limit=5&accept-language=` | Worldwide, structured address parts and coordinates; the only option that covers non-CEP countries without a key |

CEP flow: BrasilAPI; on a failure (timeout, network error, 4xx/5xx other than 404, unreadable body) or a 404, ViaCEP. Found by either: answer (`source` says which). Not found by one and the other down: 404 `address_not_found`. Both technically failed: 502 `address_lookup_unavailable`. A negative answer is cached; a failure is not.

Why not Google Places, Mapbox, HERE: keys, billing, terms that forbid caching/storing results, and the provider's address would be shared with a company that profiles queries.

## 3. API (`/api/v1`, any signed-in user, rate limited per user)
- `GET /address/lookup?cep=` -> `CepAddressResponse` `{postalCode, street|null, neighborhood|null, city|null, state|null, latitude|null, longitude|null, source: "brasilapi"|"viacep"}`. `cep` = 8 digits with an optional hyphen after the fifth; else 400 `validation_failed` (`field: cep`).
- `GET /address/search?q=&lang=` -> `{results: [PlaceResult]}`, at most 5, best first, empty list when nothing matches. `PlaceResult` = `{displayName, name|null, street|null, houseNumber|null, neighborhood|null, city|null, state|null, postalCode|null, country|null, latitude, longitude}`; `state` is the UF for Brazil (from `ISO3166-2-lvl4`), else the state name. `q` is trimmed with whitespace collapsed, 3-120 characters, no control characters (400 `validation_failed`, `field: q`); `lang` optional, a language tag (`en`, `pt-BR`; 400, `field: lang`), sent as `accept-language`. Results without usable coordinates or name are dropped.
- Errors (problem+json `code`): 404 `address_not_found` (CEP only), 502 `address_lookup_unavailable` (every upstream failed, or the server could not get a Nominatim slot in time), 503 `address_lookup_disabled` (`AddressLookup:Enabled=false`), 429 `rate_limited` (with `Retry-After`).
- Rate limit: `RequestLimits:AddressLookupPermitsPerMinute`, default 20 per user per fixed minute, both routes together, cache hits included (the global 300 still applies).

## 4. Server behaviour
- Layers: `Application/AddressLookup` (DTOs, `AddressQueryRules` validation and normalization, `IAddressLookupService`, port `IAddressDirectory`), `Infrastructure/AddressLookup` (`HttpAddressDirectory`, parsers, `AnswerCache`, options + validator, `AddAddressLookup`), `Api/Endpoints/AddressEndpoints.cs`. Typed errors are `DomainException`s mapped in `DomainExceptionStatusCodes`.
- **Identification.** Every upstream request sets `User-Agent: Lotties-baby-tracker/1.0 (+https://github.com/lotties-app/lotties.app; <AddressLookup:ContactEmail>)`; the contact part is optional but recommended for the public Nominatim (its policy asks for an identifying agent and a way to reach the operator). `ContactEmail` is validated (no spaces, parentheses, semicolons or control characters) so it cannot inject a header.
- **Nominatim usage policy.** (a) At most one request per second for the whole server: a gate spaces request starts by `NominatimMinIntervalMilliseconds` (default 1100) whoever asks; a request that cannot get a slot within `TimeoutSeconds` is refused as unavailable instead of queueing without bound. (b) No autocomplete: the web searches only on the button or Enter, and the server enforces a 3 character minimum. (c) Results are cached in memory (`SearchCacheMinutes`, default 60; key = lowercased text + language). (d) Identifying `User-Agent` (above). (e) Attribution: see 6. Heavy use needs your own Nominatim instance: set `AddressLookup:NominatimBaseUrl`.
- **Cache.** In memory per API process, TTL + a size cap (`CacheMaxEntries`, default 1000 per kind, emptied when full). CEP answers `CepCacheMinutes` (default 1440), including "not found"; searches `SearchCacheMinutes`. Keys are never logged or persisted; a restart empties them.
- **Timeouts.** Each upstream call has `TimeoutSeconds` (default 5) and a 256 KiB response cap; no redirects, no cookies.
- **No query text in logs.** The class logs the upstream name, the HTTP status or the exception *type*, never the URL, the CEP, the search text or an exception message. The framework's own HTTP client logging would print the request URL, so `appsettings.json` sets the category `System.Net.Http.HttpClient.AddressLookup` to `None`; do not raise it. ASP.NET request logging is at `Warning` (no incoming URLs). A reverse proxy's access log may still record the query string of `GET /address/*` requests: if that matters, exclude the path from its logs (docs/DEPLOY.md).
- **Configuration** (section `AddressLookup`, standard `Section__Key` env form; documented in docs/DEPLOY.md): `Enabled` (true), `BrasilApiBaseUrl`, `ViaCepBaseUrl`, `NominatimBaseUrl` (absolute http(s) URLs without a query, so a self-hosted or mirrored service can replace any of them), `ContactEmail`, `TimeoutSeconds`, `CepCacheMinutes`, `SearchCacheMinutes`, `CacheMaxEntries`, `NominatimMinIntervalMilliseconds`. Invalid values fail startup.

## 5. Web (`code/web/src/providers/`)
- `AddressFinder.tsx` sits above the Address field in `ProviderSheet`: a "Find the address" box (placeholder with a CEP and a street example), the "Find address" button, an `aria-live` region for results and messages, and, once an address is applied, "Number" and "Complement" boxes.
- **CEP, address empty:** the single answer fills the address at once. **CEP, address already typed:** the answer is offered as a one-item list to pick, so typed text is never overwritten silently. **Search:** a list of up to five places (name in bold, one-line address), tap one to fill. A pick replaces the address text (the parent chose it explicitly).
- **Composing** (`composeAddress`, pure): `Street, number - complement` / neighborhood / `City - State` / `CEP 01001-000` (a non-CEP postal code is shown as is), within 400 characters; a place with neither street nor city falls back to the service's one-line text. Typing the number or complement recomposes the text **only while the address still equals what the lookup composed** (or is empty), so the parent's own edits are never rewritten. The address stays an ordinary editable field.
- **Failures:** text shorter than 3 characters: "Type a CEP or at least 3 characters" (nothing is sent). 404/502/503/429 and a lost connection use the API-code messages (`errors.address_not_found`, `address_lookup_unavailable`, `address_lookup_disabled`, `rate_limited`, offline) followed by "You can type the address below." While the browser reports offline the button is disabled with a note. Nothing else changes: the sheet, the other fields and Save behave as before.
- Enter in the box looks up (it does not submit the sheet); IME composition is respected.
- a11y: real `<label>`s through `Field`, buttons with 48 px targets, results as a labelled list of buttons, messages with `role="alert"`/`status`, the OSM link is a normal link (new tab, `noopener noreferrer`). Layout for 320-430 px (single column, number/complement in a 1:2 grid), theme tokens only (`palette`, `optionBase`), axe tests in the light and dark schemes.
- i18n: `providers.address.*` in `locales/{en,pt-BR}/providers.json`, API error codes in `errors.json`.

## 6. Licences and attribution
- **OpenStreetMap / Nominatim:** data is ODbL; attribution "Data © OpenStreetMap contributors" is **required where results are shown**: the finder shows it, linked to https://www.openstreetmap.org/copyright, under a search result list and while the address filled from one is showing. Storing the composed text of a result in the provider's address is a "produced work" use the ODbL allows without share-alike, with that attribution; coordinates are not stored. The public Nominatim usage policy (https://operations.osmfoundation.org/policies/nominatim/) is followed as in section 4; it forbids bulk and autocomplete use and may block abusive clients, which is why a self-hosted base URL is configurable.
- **BrasilAPI** (MIT, free, community run) and **ViaCEP** (free): CEP data is public postal data; no attribution is required, none is shown. Both are best-effort services: hence the fallback and the manual field.
- No secrets, keys or accounts are involved anywhere.

## 7. Privacy summary (for the LGPD/privacy text)
When a parent presses "Find address", the CEP or search text typed in that box is sent to our server, which asks BrasilAPI/ViaCEP (CEP) or OpenStreetMap's Nominatim (text) from the server's IP address with an identifying User-Agent. The user's IP, account, device, baby and family are not sent to those services; the server keeps answers in memory for up to a day and does not log the typed text. Searching for a clinic's name or street is the only thing disclosed; the family's address is never needed (it is a doctor's or clinic's address).

## 8. Not done
- Coordinates are not stored or used (no map view, no "near me"); the `latitude`/`longitude` of the answers are available for it. No distance sorting.
- No autocomplete or suggestions while typing (policy, privacy and cost).
- No other countries' postal-code services (a search covers them); no address lookup in the appointment form's free-text place (it copies from the provider).
- No per-install allowlist of who can call it beyond sign-in and the rate limit (see 1).
