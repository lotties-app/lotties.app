# Formulas: which formula a bottle was, and what was logged on each (design, 2026-10-22)

Owner request: parents register the name of the formula they give, so Insights can later help compare formulas (belly pain, discomfort, how much the baby drinks). The app compares what was logged; it never says a formula causes or fixes anything and never recommends a formula, an amount, a threshold or a target.

## 1. Data model (per baby, synced offline-first like prescriptions)
- `Formula` (Domain `Formulas/Formula.cs`, table `formulas`, migration `Formulas`): `id` (client GUID), `babyId`, `name` (required, 1-60 characters), `brand` (optional, 60), `stage` (optional short text such as `2` or `1+`, 10), `notes` (optional, 1000), `startedOn` (optional date 2000-01-01..2100-12-31), `isCurrent`, `archived` (`is_archived`), `createdBy`, `createdAt`, `updatedAt` (server receive time, the delta cursor), `clientUpdatedAt` (client edit time, decides conflicts). Text is trimmed, NUL is rejected (400 `validation_failed`, `field`).
- Never deleted: bottles name a formula, so it is archived instead (restorable). An archived formula is never current (`isCurrent` is stored `false`).
- At most one current formula per baby. A write that makes one current makes the others not current in the same transaction (a first save clears the old one, a second save sets the new one, so the partial unique index `ux_formulas_one_current_per_baby` on `baby_id WHERE is_current` is never broken in between). The cleared formula gets `updatedAt` = now (clients learn it through the delta) and `clientUpdatedAt` = the client time of the write that caused it (never moved back), so an older offline write that would make it current again loses under last write wins. A lost race on the index (two parents at the same moment) is 409 `concurrent_modification` (`retryable: true`); the web outbox retries it with backoff instead of dead-lettering it.
- Feeding events reference it: the built-in feeding type declares two hidden text fields, `formula_id` (a GUID of a formula of the same baby, archived ones included so offline bottles still sync) and `formula_name` (a copy of the name when logged, at most 60 characters), both visible only when `bottle_feeding_type` = `formula` (and so only for `method` = `bottle`). The name snapshot keeps the history right after a rename or an archive. The server checks the reference on create and when an edit changes the payload (400 `validation_failed`, `field` `formula_id`); older bottles and the Napper importer's have neither member and stay valid.

## 2. API (`/api/v1/babies/{babyId}/formulas`)
- `GET ?since=` (any member): the baby's formulas changed at or after `since` (all without it), archived included, by `(updatedAt, id)`. `FormulaDto` = `{id, babyId, name, brand, stage, notes, startedOn, isCurrent, archived, createdBy, createdAt, updatedAt, clientUpdatedAt}`.
- `PUT /{formulaId}` (Owner, Parent): full state `{name, brand?, stage?, notes?, startedOn?, isCurrent, archived, updatedAt?}`; 201 created (with `Location`) or 200. Idempotent (a replay changes nothing), stale client time ignored (200, stored copy), an id of another baby 409 `formula_baby_mismatch`. Create, edit, set as current and archive are all this one route.
- No `DELETE` (405).
- Role decisions (EndpointRoleMatrixTests): `GET` Read (Owner, Parent, Caregiver, Viewer), `PUT` Write (Owner, Parent). A Caregiver picks a formula when logging a bottle: the events `PUT` (Log) accepts `formula_id` from her. The Doctor role does not exist yet.

## 3. Web
- Dexie schema v4 table `formulas` (`id, babyId, [babyId+updatedAt]`), pulled after prescriptions and before events (`pullFormulas`, cursor `formulas`), pushed through the outbox (`entityType: 'formula'`). `dependencyOf` pushes a formula before a bottle that names it (also when a later edit absorbed its create); a bottle the server rejects on `formula_id` while its formula is still queued waits for it instead of being dead-lettered. Purged with the baby's other rows.
- Current formula on the device: `currentFormula` = the one marked current and not archived; if a pull lags and two are marked, the newest edit wins (as on the server). Local commands never touch the other formulas: the server clears them and the delta brings them back.
- Bottle sheet: when the content is formula the sheet shows the baby's formulas as chips, sorted by name. A new bottle (or a timer stopped with "Finish this bottle" that names none) preselects the current formula, else the formula of the newest bottle that named one; tapping the selected chip again names none. Editing a logged bottle never fills one in on its own. Owners and Parents also get "+ New formula": a small sheet with the name only and suggestions while typing (`formulas/formulaSuggestions.ts`, a small neutral list of common Brazilian names with stages, a typing aid only, no catalog, no claims). A new formula becomes the current one when the baby has none. Caregivers pick but do not add; with no formula at all the chips are hidden.
- Quick logs: a bottle of formula from the Feed tray names the current formula silently (none without a current formula). The Bottle timer asks for it at the stop together with the amount and content, as above.
- Day: the detail line of a bottle reads `120 ml · Formula · Nan 1` (the snapshot).
- Settings > Formulas (per baby): the list by name with a "Current" badge, details (brand, stage, since, notes), add and edit (name with suggestions, brand, stage, started on, notes, "Current formula"), set as current (star), archive with Undo, an "Archived" list with restore. Read-only for Caregivers and Viewers.

## 4. Insights: the Formulas card (`insights/formulaComparison.ts`, pure)
- Look-back: the last 30 local days (not the range switch: a comparison needs both periods).
- A formula's period = the local days with at least one bottle naming it; a day with bottles of two formulas counts for both, each with its own bottles. Days are local calendar days (DST safe).
- Per formula, averaged over its finished days (today only when it is the only day): bottles per day; bottle ml per day (sum of `amount_ml` of its bottles, days with an amount only); ml per kg per day (days with an amount and a weight: the nearest weight measured on or before the day within 14 days, else the nearest after it within 14 days; skipped without one; weights from the growth measurements online plus the device's latest weight); belly pains per day (all belly pain events of the day); belly pains starting within 2 hours after one of its bottles (from the bottle's start to 2 h after its end, each episode once, on the day of the newest such bottle: a pain at 00:30 after a 23:30 bottle counts on the bottle's day); fussy spells per day; dirty diapers per day (`DIRTY` or `MIXED`). A kind the family never logged in the 30 days has no average (no "0 fussy spells a day" for a family that does not log them).
- Unlock: a formula shows with at least 7 days and 20 bottles. The card shows when at least one formula qualifies: one alone (its averages as headline numbers), two or more side by side; the others are readiness rows "Formula: Nan 1, Day 4 of 7" ("Shows after N more days with this formula", then "... N more bottles ..."). Without a qualifying formula, formulas in use are rows under "On the way" (or in "More insights are coming").
- Card: the statements first, then always the plain note, the period of each formula (dates, days, bottles), then one small bar per formula for each measure (scaled to the largest value; numbers always shown as text), or "View as table" (measures as rows, formulas as columns). Light, dark and night through the chart tokens.
- Wording: only "While on Aptamil 2: 0.2 belly pains/day, on Nan 1: 0.4." style statements (belly pains, fussy spells, bottle milk), always followed by: "This compares what you logged. Many things change over time (age, growth, illness), so it does not show that a formula causes anything. Talk to your pediatrician before changing a formula or the amount." (pt-BR: "Isto compara o que você registrou. Muita coisa muda com o tempo (idade, crescimento, doenças), então isto não mostra que uma fórmula causa alguma coisa. Converse com o pediatra antes de trocar a fórmula ou a quantidade."). Never "better", "worse", "causes", "should", a recommendation, a target or a threshold.
