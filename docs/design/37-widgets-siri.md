follows the same data contract later. **Status (2026-10-31): written, not yet compiled or run.** There is no Xcode on the
development machine; the workflow `.github/workflows/ios-compile-check.yml` (unsigned build on a macOS runner) is the

## 1. Decisions (owner, 2026-10-31)

| Question | Decision |
| --- | --- |
| What does a Siri phrase, widget button or quick action do? | **Logs the event at once**, offline, and syncs later. No confirmation sheet. |
| First cut | **iOS only** (WidgetKit + App Intents). Android widget and shortcuts later, same contracts. |
| Where do the intents run | In the **app target** (App Intents work without an extension since iOS 16), so there is one extension only: the widget. |

Minimum iOS for the new code: 16 (the Xcode project says 15 today; the App Intents and widget code is guarded with
`@available(iOS 16, *)` or the target version is raised, an owner decision at step 2).

## 2. Data flow (the app is offline-first; neither widget nor intent talks to the network)

```
web app (WebView, Dexie)  --writeSnapshot-->  App Group container  <--reads--  widget (WidgetKit)
                                                      ^   |
Siri / widget button (App Intent) --append--> outbox  |   +-- app drains the outbox on launch and resume,
                                                          turns each entry into a normal local event (same write path
                                                          as the UI), then removes it
```

App Group: `group.app.lotties.app`, shared by the app and the widget extension. Both files live in its container, not in
the WebView's storage (a native process cannot read IndexedDB).

### 2.1 `widget-snapshot.json` (written by the app)

```json
{
  "version": 1,
  "updatedAt": "2026-10-31T21:05:00Z",
  "signedIn": true,
  "selectedBabyId": "<guid>",
  "babies": [
    {
      "id": "<guid>",
      "name": "Ana",
      "sleep": { "state": "asleep", "startedAt": "2026-10-31T20:40:00Z" },
      "lastFeed": { "at": "2026-10-31T19:10:00Z", "kind": "bottle", "amountMl": 120 },
      "lastDiaper": { "at": "2026-10-31T20:05:00Z", "kind": "wet" }
    }
  ]
}
```

Times are absolute; the widget renders "x min ago" itself, so it stays right without the app. `signedIn: false` (or a
missing file) makes the widget show "Open Lotties". The app rewrites the file after every local event write and after
each sync pull (one writer function, only when `isNativeApp()`), and **deletes it on sign-out** and when the account's
local data is cleared (docs/design/12 "per-account local data").

### 2.2 `widget-outbox.json` (appended by intents, drained by the app)

```json
[
  { "id": "<client guid>", "babyId": "<guid>", "type": "feed", "occurredAt": "2026-10-31T21:07:12Z",
    "payload": { "kind": "bottle", "amountMl": null }, "source": "siri" }
]
```

The `id` is the event GUID the client generates (project convention), so draining is an idempotent upsert: a crash after
the write and before removing the entry just writes the same event again. `type` and `payload` use the app's own event
types and payload shapes (code/web, per-kind payload), never new ones; the exact mapping is step 3. File access from the
widget and the intent goes through `NSFileCoordinator` (two processes can touch it).

## 4. Signing impact (this changes the manual signing of docs/MOBILE-RELEASE.md 4.3)

The widget is a second bundle with its own App ID and profile, and both bundles need the App Group capability.

1. **Owner, developer portal** (needs no Mac):
   - Identifiers > **App Groups** > **+**: `group.app.lotties.app`.
   - Identifiers > `app.lotties.app` > enable **App Groups** and select that group > Save.
   - Identifiers > **+** > App IDs > App: `app.lotties.app.widgets`, enable **App Groups** with the same group.
   - Profiles: **regenerate** the existing `Lotties App Store` profile (a capability changed, the old one no longer
     matches) and create `Lotties Widgets App Store` (App Store Connect distribution, the new App ID, the same
     distribution certificate).
   - Secrets: replace `IOS_PROFILE_BASE64`, add `IOS_WIDGET_PROFILE_BASE64` (same commands as 4.3 step 5).
2. **Workflow** (assistant): install both profiles; export with a `provisioningProfiles` map with both bundle IDs.
   **The archive stops passing `PROVISIONING_PROFILE_SPECIFIER` on the command line** (one value would apply to both
   targets): each target carries its own profile name in the Xcode project (Manual style, distribution identity).
3. The App Store Connect API key is unchanged (upload only).

## 6. Privacy and safety

- The snapshot and the outbox hold a child's data on the device only, in the app's own App Group container; they are
  deleted on sign-out and account erasure, and never uploaded by themselves.
- Lock-screen variants hide names by default.
- Intents need no network and no token: they only append to the outbox; the app, signed in as the account, does the write.
- If the outbox holds entries for an account other than the signed-in one (a sign-out and another sign-in in between),
  they are dropped, not applied: entries carry no account id, so the outbox is cleared on sign-out.

## 8. Siri through the MCP server (decided 2026-10-31, after the widget shipped)

The owner asked for Siri to mirror the Alexa intents, answered by the same server. So the Siri and Shortcuts intents are
**MCP clients** (supersedes the "log at once, offline" decision of section 1 for Siri; the **widget buttons keep it**):

- `App/LottiesSiriIntents.swift`: about 45 App Intents (the Alexa model's reads and logs that the MCP server has a tool for;
  medication has none by design), each one `tools/call` of the matching tool, speaking the answer. All are in Shortcuts and
  Spotlight; only some have spoken phrases (`App/LottiesShortcuts.swift`), because iOS allows **ten** App Shortcuts per app.
  The spoken ones are redesigned (2026-11-01) as 8 shortcuts (2 left spare), four of them generic: an `AppEnum` parameter
  sits inside the phrase, so one slot covers many things. Siri matches the enum case's display title, which is localized.
  1. Diaper: "Log a diaper", "Diaper change", "Log a {wet|dirty|both} diaper" (`SiriLogDiaperIntent`, default wet when not said).
  2. Bottle: "Log a bottle". 3. Breastfeed: "Start a breastfeed".
  4. Sleep: "Baby {fell asleep|woke up}" (`SiriSleepChangeIntent`, `log_sleep_start`/`log_sleep_end`). The old separate phrases are gone.
  5. Activity: "Log {activity}", "Start {activity}" (`SiriLogActivityIntent`; bath, tummy time, belly massage, nasal suction,
     nail trim, skin care, outdoor time, fussy, spit-up, teething, breast pump). Optional `minutes` (1..720) is sent as the MCP
     argument `minutes` only for the activities whose tool takes a duration (tummy time, breast pump, belly massage, fussy, outdoor);
     bath, nasal suction, nail trim, skin care, spit-up and teething never ask and never get it. For the duration ones Siri asks "How many minutes?" when it was not given; "zero" sends nothing
     and the server starts a timer.
  6. Health: "Log {temperature|symptom|belly pain}" (`SiriLogHealthIntent`); temperature and level are asked after. The symptom
     is logged without a choice, as before (the tool takes an optional choice from a list, not wired yet; no free text).
  7. Ask: "Ask {topic}" (`SiriAskIntent`): last feed, next nap window, next feed, next diaper change, last diaper, diapers
     today, bottles today, feeds today, sleep today, day summary, week summary, next appointment, vaccines due. "When was the
     last feed" is dropped as a phrase (it stays an intent in Shortcuts).
  8. Undo: "Undo the last entry" (asks to delete; the app confirms).
  What cannot be done: a number cannot be inside a phrase (only `AppEnum`/`AppEntity` can), so "15 minutes of tummy time" in one
  sentence is not possible, Siri asks for the minutes next; there is no timer shortcut (the server has no pause/stop tool);
  no medication shortcut (no MCP medication tool by design). Phrases and titles are localized: Phrases and titles are localized: `App/en.lproj` and `App/pt-BR.lproj` `AppShortcuts.strings` (key = the English phrase with `${applicationName}`) and `pt-BR.lproj/Localizable.strings` (intent titles, descriptions, parameters). Pt-BR phrases name the app as "no Lotties" ("Registrar fralda no Lotties").
- `App/LottiesMcp.swift`: the sign-in (`ASWebAuthenticationSession`, PKCE, public client `lotties-ios`, scopes
  `lotties.read lotties.write offline_access`, redirect `app.lotties.app://siri/callback`), tokens in the Keychain (never in the
  App Group files the widget reads), refresh, and the JSON-RPC call (`Authorization: Bearer`, protocol 2025-11-25, one POST,
  no initialize). Keycloak setup: docs/MCP.md 3.4.
- Spoken sentence: the server renders it with the Alexa language classes when the request has the header
  `Lotties-Speech-Locale: pt-BR|en-US` (`structuredContent.speech`), so Siri says what Alexa says, in the phone's language.
- The web app starts the sign-in: Settings > Voice assistants > Siri and Shortcuts (`SiriConnectPanel`), through the WebKit
  message handler `lotties` (`siriStatus`, `siriConnect`, `siriDisconnect`; also used by the widget bridge). Logout and
  account erasure call `clearAll`, which also drops the Siri tokens.
- Offline: a Siri request needs the network (it says nothing was logged). No outbox fallback, to avoid double events when
  an answer is lost; idempotency keys make a retry safe. The widget buttons still work offline.
- The old offline intents (`LogDiaperIntent`, ...) stay for the widget buttons and are hidden from Shortcuts
  (`isDiscoverable = false`).

## 9. Next-up estimates and the "coming up" highlight (2026-11-01)

The snapshot carries the Now screen's estimates per baby: `nextNap {earliest, expected, latest}`, `nextFeed {at, amountMl?}`,
`nextDiaper {at, kind}`, built by `widgets/snapshot.ts` from the last predictions the app fetched (localStorage cache),
the cached age norms and the local events (`deriveNowState` and `upcomingToday`, the same code as the Now screen); no
network. Estimates only, never advice.

- Shown as "Próxima soneca 14:20", "próx. 15:10" (only while still ahead).
- **Coming up** (`WidgetSnapshot.Baby.due(at:)`): from 20 minutes before an estimate until 30 minutes after it (owner choice).
  That action's tile gets the category colour on its border and a tinted fill (the icon stays: a bell hid which action
  it was, owner feedback 2026-11-01); the sleep button turns into a filled "Soneca 14:20" while the nap estimate is coming up and the baby
  is awake. The wording stays a time, not an order ("estimates, not alarms").
- The widget timeline has an entry at each moment a highlight starts or stops (`dueChanges`), so it changes without the app
  opening; views read the entry's date from the environment (`lottiesNow`), never `Date()`.
- Logging from a widget button or Siri clears the matching estimate at once; the app republishes real ones when it opens.
- Staleness: the estimates are as old as the last time the Now screen fetched predictions online.

## 10. Choosing the buttons, and the Activities widget (2026-11-01)

- The Summary and Quick-actions widgets are configurable (iOS 17, `AppIntentConfiguration`, `LottiesButtonsIntent`):
  "Edit widget" picks what each of three buttons logs, from `WidgetActivity` (bottle, breast, diaper, bath, belly massage,
  tummy time, nasal suction, nail trim, skin care, outdoor, fussy). The sleep button stays. The widget extension's
  deployment target is 17.0 (the app stays 16.0; widget buttons already needed 17).
- The fixed **Activities** widget (medium) has a button for each of the eight non-everyday activities.
- One intent logs them all (`LogActivityIntent`, hidden from Shortcuts). Bottle and diaper keep their behaviour. The other
  activities go to the outbox as `type: "activity"` with `payload.kind` = the event type key; the app creates an instant
  event, or a running one when the type has a duration (stop it in the app), through `createEvent`. A key outside
  `widgets/activities.ts` or a type the baby lacks is dropped.
- The snapshot carries `lastActivity` (type key to last start, 3 days back) so rows can say "há 3 h".
- Picker names in "Edit widget" follow the phone language (English literals; the tiles follow the app language).

## 11. Choices inside the widget, More, and the running feed (2026-11-01)

- A tap on Diaper, Bottle or Breast no longer logs a guess: the widget swaps its buttons for the choices (Wet, Dirty, Both;
  the last bottle's ml plus 60, 90, 120, 150; Left, Right) and the tap on one logs it. The open choice lives in the App Group
  defaults (`LottiesPicker`, 25 seconds); the timeline has an entry at its end, so the buttons come back by themselves, and
  a close button (x) puts them back at once. No app, no network.
- **More** (the dots button; the fourth tile of the quick and large widgets) opens the list of every activity.
- A bottle or breastfeed running now is in the snapshot (`runningFeed`: kind, effective start, paused, elapsed). The widgets
  show it with its timer and, for the bottle, pause or resume, plus stop. The buttons write `feed_pause`, `feed_resume`,
  `feed_stop` to the outbox; the app applies them to the running feeding event (`pauseTimer`, `resumeTimer`, `stopEvent`;
  `stopNursing` for the breast). Pausing from the widget does not ask how much is left in the bottle.
- The breast choice carries the side (`payload.side`) to `startNursing`.

## 12. Clean rows (2026-11-01)

The medium widget's rows were cut ("2 hrs,... · próx....") and busy (borders, a plus icon). Now: a narrow left column (name, sleep state, the
time, the sleep button) and a borderless list on the right. Each row is icon, name, and on the right how long ago the last one
was, said outright ("há 35 min", "há 2 h+", "há 2 h 30+": minutes under an hour, then rounded down to the half hour with a plus; `LottiesText.agoRounded`); the estimate ("próx. 11:30") sits under the name when there is one, and only the
row that is coming up gets a tinted fill. The last row is "Mais" (the list of every activity). The "ago" is computed per timeline
entry (at most 15 minutes old) instead of ticking live; the lock screen and the single-purpose widgets keep the live text.

- Privacy: names show on the home screen, as on iOS; on a lock-screen host (keyguard category, not declared today) they

- Tests (plain JVM): `app/src/test/java/app/lotties/app/widgets/` (ago rounding, the due window and its changes, choice
  expiry, bottle amounts, quick tiles, the refresh plan, the outbox shapes `parseOutbox` accepts, the snapshot update,
  ISO parsing).

Differences from iOS: no "Edit widget" configuration (the buttons are the iOS defaults Bottle, Diaper, Breast; a
configuration Activity is not done); no large size, no lock-screen or single-purpose Sleep/Feed/Diaper widgets; the open

inset.

Unverified: everything on a real launcher (no device or emulator test): layout at real cell sizes (launchers differ in

`lotties-android`). The plugin reads the discovery document, opens the system browser (a Custom Tab when the browser
supports it: only the `android.support.customtabs.extra.SESSION` extra, no androidx.browser dependency) with PKCE S256 and
scopes `openid offline_access lotties.read lotties.write`; the redirect `app.lotties.app://siri/callback` reaches
`MainActivity` (intent filter host `siri`, next to `auth`) and the plugin through `handleOnNewIntent`. The state must
match; a missing code (consent denied) or coming back without a redirect resolves `connected: false` (cancelled). The
PKCE verifier lives in memory only: if Android kills the app while the browser is open, the person taps Connect again.
Keycloak client: docs/MCP.md 3.5 (owner step). Every call sends `Lotties-Client: android` (adapter `android`, PR #28),
`MCP-Protocol-Version: 2025-11-25` and `Lotties-Speech-Locale` (the app language from the widget snapshot's `language`,
else the phone's; only `pt-BR` or `en-US`). Write tools get a fresh `idempotencyKey`.

Sign-out and erasure: `endSession` calls `LottiesShared.clearAll`, which on Android also deletes the voice file and its
Keystore key (`LottiesSharedPlugin.clearAll`), as the iOS message handler drops the Siri Keychain item. Disconnect does the
same for the voice part only.

### 14.1 Entry points and what they call

Twelve static shortcuts (Android allows a few more; the launcher shows the first four or five on a long-press of the
icon, all of them can be pinned to the home screen). Each starts `VoiceActivity` with the extra `feature` = its id.

| Shortcut id | Label (en) | MCP tool and arguments (same as the Siri intent) |
| --- | --- | --- |
| `diaper_wet`, `diaper_dirty`, `diaper_both` | Wet diaper, Dirty, Wet+dirty | `log_diaper {kind: wet/dirty/both}` |
| `bottle` | Bottle | asks "How many ml?" from 30..240 (step 30), then `log_bottle {amountMl}` (content omitted: the tool says to omit it when unknown) |
| `breastfeed` | Breastfeed | `log_nursing` |
| `fell_asleep`, `woke_up` | Asleep, Woke up | `log_sleep_start`, `log_sleep_end` |
| `activity` | Activity | pick one of the 11 `SiriActivity` activities; for tummy time, breast pump, belly massage, fussy and outdoor also pick minutes (start a timer, 5..60) and `minutes` is sent only when 1..720; the other six never get it |
| `health` | Health | temperature (36.0..40.0 °C by 0.2) `log_temperature {temperatureC}`; belly pain 1..5 `log_belly_pain {level}`; symptom `log_symptom` (no choice, as on iOS) |
| `ask_last_feed` | Last feed | `get_last_feed` |
| `ask` | Ask | pick one of the 13 `SiriAskTopic` questions (`get_*`) |
| `undo` | Undo | `request_delete_last_entry` (the app asks the parent to confirm; assistants never delete) |

No medication entry (no MCP tool by design), no free text anywhere: every value is a fixed choice. The answer is the
server's sentence (`structuredContent.speech`, the Alexa wording of docs/design/32), shown in a Toast and spoken with
TextToSpeech in the speech locale; local texts only cover failures (not connected, offline: "nothing was logged",
refused, no answer), as `SiriSay` does. The choice dialogs and the local texts use the speech locale too (the app bundle
keeps every language: `bundle.language.enableSplit = false`). Not connected: the Toast says so and the app opens on
Settings > Voice assistants (`app.lotties.app://siri/settings`). The network call runs after the activity has closed, so
no invisible window stays over the home screen.

### 14.2 Google Assistant (App Actions)

`shortcuts.xml` declares the built-in intent `actions.intent.OPEN_APP_FEATURE` (it exists in the current BII reference,
Common category; it requires inline inventory for its `feature` parameter, and its user invocation lists en-US and pt-BR
among the locales). The twelve shortcuts are that inventory (`capability-binding`, synonyms = the long and short labels,
arrays in `values/voice_strings.xml`, so they follow the language). Assistant sends the matched shortcut id as the extra
`feature` to the exported alias `.voice.VoiceAssistantEntry`. Phrases are of the form "Open wet diaper in Lotties" /
"Abrir xixi no Lotties": the BII is about opening a feature, and logging is a stretch of it; there is no BII for "log a
baby event", and none was invented. Because any app can start an exported component, **a write through that alias asks
for one tap** ("Log this now?"); questions are answered at once (the answer is shown and spoken, never returned to the
caller). Launcher shortcuts start the non-exported activity and log at once.

## 15. The adaptive "Lotties" widget (2026-11-02)

One more widget kind, `LottiesAdaptiveWidget` (small, medium, large), added next to Summary, Quick actions and Activities,
which stay as they are (removing a kind leaves blank widgets on home screens). It takes the same "Edit widget" buttons
(`LottiesButtonsIntent`) and shares the code of the others (`SummaryMedium`, `QuickItemTile`, `SleepSquare`, `PickerPanel`).

iOS widget sizes are fixed: the person picks small, medium or large when adding it, and cannot drag it bigger afterwards
(Android can, section 13). So the "grows with the size" idea is one widget that adapts its content to the size added,
using the same tiers as the Android widget (section 13):

| Size | Content |
| --- | --- |
| Small | Name, the sleep state's icon and live timer on one line, then four tiles: the three chosen buttons (pause and stop while a feed runs) and the sleep tile (framed while the nap is coming up). |
| Medium | The Summary content: sleep column (state, timer, next nap, sleep button) and the rows (the running feed first, the chosen buttons with "há X" and estimates, the coming-up row tinted, More). |
| Large | The medium content and, under it, the eight activities (`WidgetActivity.panel`). |

Choices (Wet/Dirty/Both, ml, side) replace the content at any size; in the small widget the ml go in two rows of two, and
a More opened from another widget is ignored (the list of activities does not fit). No lock-screen families: Summary keeps them.
Unverified until a device runs it: the layout at each size and the interactive buttons (the compile check only builds it).
