# Design spec (pass 1: foundation, Home, Track sheet, sleep presets)

Inspiration: Napper's layout patterns (hero prediction, one-tap track grid, centre "+" action). Own look: no copied artwork, names or icons. Decided with the user on 2026-10-21: night-sky dark by default (light follows the system setting), "Fell asleep" = marker AND timer start, pass 1 = foundation + Home + Track sheet + sleep presets. Pass 2 (later): Timeline polish, Insights charts (sleep area chart, bedtime/wake bars), Growth, Settings polish.

## 1. Foundation (theme)
MUI theme with CSS variables, `colorSchemes` light + dark; default dark unless the OS says light; the manual toggle in Settings > Appearance stays (system / dark / light).

Dark ("night"): background `#15132e`, surface `#1f1c3f`, surface-raised `#2a2468`, hairline `#2a2652`, text `#eceaff`, text-muted `#9d99c8` (must pass AA 4.5:1 on surface), accent `#7c6cf0`, accent-soft `#c4baff`.
Light ("day"): background `#f6f5ff`, surface `#ffffff`, surface-raised `#ebe8ff`, hairline `#e0ddf5`, text `#1b1838`, text-muted `#5d5a82`, accent `#5b4bd6`, accent-soft `#4a3cc0`.
Category colours (icon on a tinted circle; tint = colour at ~18% over surface, icon = the stronger tone; define as theme tokens `category.{sleep,feeding,diaper,health,care,custom}.{bg,fg}` for both modes): sleep indigo (`#3a2f7a`/`#c4baff` dark), feeding teal (`#16423f`/`#7ee0b8`), diaper amber (`#4a3322`/`#ffc58a`), health rose (`#4b2a33`/`#ff9fb2`), care sky (`#183f55`/`#8fd8ff`), activity yellow (`#4a3d1a`/`#ffd77a`), night-waking violet (`#4a2f55`/`#f0b6ff`), custom neutral. Derive light-mode pairs with the same hues (light tint bg, dark fg), contrast AA for the icon on the tint.
Shape: cards radius 18px, tiles 16px, chips/pills 999px, bottom sheet top radius 24px. No hard borders on cards in dark (use surface contrast); 1px hairline only for dividers. Elevation: none in dark, a soft shadow in light. Typography: system UI stack; sizes: title 20/500, card title 15/500, body 14/400, caption 12/400 (never below 12px), numbers in hero 28-32/500 with tabular numerals. Touch targets >= 44px. Motion: 150-200ms ease-out; respect `prefers-reduced-motion` (no ring animation, no sheet slide).
PWA `theme_color`: dark `#15132e`, light `#f6f5ff` (media meta) and manifest `background_color` `#15132e`.
App shell: content column max-width 480px centered on wide screens, page background fills the viewport; safe-area insets honoured (`viewport-fit=cover` already set).

## 2. App shell
- Header (not a heavy coloured bar): transparent over the background. Left: baby avatar (initial on a colour derived from the baby id; photo later) + name (title) + age line ("2 months, 3 weeks", "11 days", "1 year, 2 months") in caption/muted; tap opens the baby switcher when >1 baby. Right: sync indicator icon button (cloud-done = synced, cloud-upload with count badge = pending, cloud-off = offline, error = warning tone; tap opens Settings > Sync) and the account avatar menu.
- Bottom navigation: Home, Timeline, centre FAB "+" (elevated 56px accent circle, opens the Track sheet; becomes "x" while open), Growth (ruler/chart icon, different from Timeline), Settings. Labels shown for the four items, FAB has aria-label "Add event". Hidden for Viewers? No: FAB is hidden for Viewers (read-only), nav otherwise unchanged.

## 3. Presets (the Track tiles)
A preset = one-tap action backed by an event type: `{ id, label, categoryColour, icon, typeKey, mode: 'timer' | 'instant' | 'sheet', payloadDefaults }`. Built-in presets are defined in web code (`code/web/src/presets/`), keyed by built-in type keys; every enabled custom event type automatically becomes a preset (`timer` if hasDuration else `sheet`, `custom` colour). Order as in the Track sheet below; the Home shortcuts show the user's pinned four (default: Wake-up, Feeding, Diaper, Nap; "Edit" in the Track sheet lets the user pin/reorder, persisted per baby in localStorage).
Built-ins (typeKey, mode, payload):
1. Wake-up: sleep, `instant`, kind `woke_up`. If a sleep timer (nap/night) is running, tapping Wake-up also stops it at the same moment (one transaction, two outbox entries).
2. Nap: sleep, `timer`, kind `nap` (start of the timer = when the baby fell asleep).
3. Bedtime: sleep, `instant`, kind `bed_time`.
4. Fell asleep: sleep, `instant` marker, kind `fell_asleep`, AND starts a sleep timer in the same tap with kind inferred: `night` if a bedtime marker was logged in the last 3 hours or local time is 19:00-05:00, else `nap`. The inferred kind is shown on the running-timer card and editable.
5. Night waking: sleep, `timer`, kind `night_waking`.
6. Bottle: feeding, `timer`, method `bottle`: tap starts a bottle timer, stop finishes it and asks for the optional amount_ml and bottle_feeding_type (only while the amount is missing); pause/resume as for nursing. The duration is how long the baby took to drink it. (History: until 2026-10 this was a `sheet` preset logging an instant end=start; such bottles show no duration.)
7. Nursing: feeding, `timer`, method `breast`, with left/right seconds fields in the stop sheet.
8. Diaper: diaper, `sheet` (content required).
9. Medication: medication, `sheet` (catalog checklist).
10. Belly pain: belly_pain, `sheet` (intensity 1-5).
10b. Nasal suction: nasal_suction, `sheet` (instant; optional tool bulb|electric|mouth and saline switch; health category, wind icon, no illustration yet; not pinned by default). Added after this list was written, like Pumping (breast_pump, `timer`) after Nursing.
10c. Belly massage: belly_massage, `timer` (like Tummy time: tap starts it, stop ends it at once; optional reason gas|constipation|colic|other and "Did it help?" yes|a_little|no, filled in the event sheet; health category, massage icon, no illustration yet; not pinned by default; Day detail line `Gas · helped`). Added after this list was written.
10d. Fussy: fussy ("Fussy / crying", pt-BR "Choro / irritação"; preset label Fussy / Choro), `timer` (like Tummy time; optional intensity mild|moderate|intense and "What helped" feeding|rocking|pacifier|massage|sleep|other|nothing, filled in the event sheet; care category (soothing is care, not a symptom), crying-face icon (Tabler `mood-cry`), no illustration yet; not pinned by default; Day detail line `Moderate · rocking helped`). Added after this list was written; it feeds the evening fussiness pattern (docs/design/11-patterns.md section 7).
11. Bath: bath, `sheet` (instant; optional end time field is a later backlog item #18).
12. Tummy time: tummy_time, `timer`.
13. Custom (dashed tile): opens Settings > Event types (Parent+).
Tiles in the Track sheet: two columns, each tile = tinted icon circle, name (15/500), and a status line (12, muted): "Last 2h ago" / "Last 07:05" (>= 12h shows time) / "Not tracked today" / "Running 0:42" (accent colour). Running timers are visually highlighted (accent ring). Viewers: tiles disabled with the status line only.

## 4. Home screen (top to bottom)
1. Hero prediction card (`surface`, 18px): label "Next nap" (or the soonest relevant prediction: sleep, else feeding), progress ring 128px (stroke 8, track = hairline, progress = accent, round caps) with centre text "in 24 min" (28/500) and "around 14:20" (caption). Ring progress = elapsed since the last event of that type / expected interval, clamped 0-100%. Under it: confidence chip (Low / Medium / High, tinted) and a "Why?" text button opening a small sheet with `reason`. Staleness: if the expected time is more than 2 hours in the past or the last event of that type is older than 24 h, replace the ring by a calm empty state ("Log a few events and predictions will appear here", with the Track button) instead of "Overdue/yesterday" wording; if expected is within the past 2 hours show "due now". Wording: relative times ("in 24 min", "due now"), clock times in local 24h or the locale; never "yesterday 07:18".
2. Running timers: pinned card(s) in surface-raised: category icon circle, "Nap running", "Started 13:02, 0:42" (live), Stop button (pill, high contrast). Several timers stack. Tap the card to edit.
3. Other predictions: a horizontal row of compact chips ("Feeding around 15:10", "Diaper around 14:40"), hidden when stale; "Not medical advice" line only inside the Why? sheet and once as a quiet footer caption on Home (12px muted).
4. "Today" strip: three metric cards (Sleep total "5h 10m" incl. running sleep, Feeds count, Diapers count) for the local day, from Dexie.
5. Track: section header "Track" + "Edit" (pin/reorder); four pinned preset tiles (compact vertical tiles, icon + label); a "See all" link opens the Track sheet.
Empty state (no baby yet): friendly illustration-free card with the create-baby form. Skeletons while Dexie loads. Large screens: same single column, max 480px.

## 5. Track sheet
Opened by the FAB: modal bottom sheet (24px top radius, drag handle, max height 90vh, scrollable), title "Track" + "Edit". Grid as in section 3. Choosing a preset: `timer` starts immediately (haptic-free, with an Undo snackbar 5 s), `instant` logs immediately with an Undo snackbar for the pure markers (Wake-up, Bedtime, Fell asleep); `sheet` presets close the Track sheet and open the existing EventSheet prefilled (type, payload defaults, start = now).
Undo = soft delete of the just-created event(s) (and restores a stopped timer for Wake-up).

## 6. Copy
Sentence case, no exclamation marks, no "successfully", contractions fine ("Couldn't save. Try again"). Relative times in the hero, absolute times in lists. Empty states invite an action.

## 7. Accessibility
All icon-only buttons have aria-labels; the ring has an accessible text equivalent ("Next nap in 24 minutes, around 14:20, medium confidence"); focus-visible rings in accent; contrast AA for all text/tile combinations in both themes; timers announce start/stop via a polite live region; supports 200% zoom and landscape.

## 8. Acceptance
Matches the mockup structure; light and dark both usable; no horizontal scroll at 320px width; Lighthouse accessibility >= 95 if measurable (not available locally: verify with axe-core in unit/e2e tests instead); existing unit and e2e tests updated and green.

## 9. Internationalization (en, pt-BR first)
Decided 2026-10-21. Languages: English (`en`, source/fallback) and Brazilian Portuguese (`pt-BR`). More languages must be addable by dropping in one catalog file and one entry in the language list.
- Library: `i18next` + `react-i18next` (+ `i18next-browser-languagedetector` only if it stays small; otherwise detect manually from `navigator.languages`). Catalogs are JSON in `code/web/src/i18n/locales/{en,pt-BR}.json`, namespaced by feature (`common`, `nav`, `home`, `track`, `presets`, `timeline`, `settings`, `growth`, `import`, `errors`, `eventTypes`, `predictions`, `auth`, `pwa`). Non-English catalogs are lazy-loaded (dynamic import); `en` is bundled.
- Locale selection: setting `system | en | pt-BR` in Settings > Language (also first in the Appearance area), default `system` (match `navigator.languages`, `pt`/`pt-PT` map to `pt-BR`, otherwise `en`), persisted in localStorage (try/catch). Sets `<html lang>`. Changing it applies immediately without reload.
- Every user-visible string goes through `t()` (including aria-labels, placeholders, snackbars, dialog buttons, empty states, validation messages, document title and PWA install hints). No string concatenation: use interpolation and ICU-style plurals via i18next plural keys (`_one`, `_other`; pt-BR also uses `_many` only if needed). Never build sentences from fragments.
- Dates, times, numbers, durations, relative times: only through `Intl` (`DateTimeFormat`, `NumberFormat`, `RelativeTimeFormat`, `ListFormat`) with the active locale, via small helpers in `code/web/src/i18n/format.ts` (formatTime, formatDate, formatDuration, formatRelative, formatAge, formatNumber, formatUnit). 24-hour clock for pt-BR. First day of week from the locale.
- Server-provided text: the API keeps returning stable machine codes and keys; the web owns the wording.
  - Built-in event types, their fields and select options are rendered from the key: `eventTypes.<typeKey>.name`, `eventTypes.<typeKey>.fields.<fieldKey>.label`, `...options.<optionValue>`; fall back to the server `name`/`label` when no translation exists. User-created types, fields, options and medication names are user content and are never translated.
  - Problem details: map `code` to `errors.<code>`; fall back to a generic localized message, never show server `detail` text raw.
  - Predictions: render the sentence from the structured `basis` and numbers (median gap, sample count, look-back days, age band, day phase), not the server `reason` string; the server `reason` stays English as a debugging fallback only.
- Copy style per language: English sentence case (see section 6). pt-BR: informal "você", sentence case, no exclamation marks, natural not literal ("Registrar", "Hora de dormir", "Soneca", "Despertar noturno", "Acordou", "Adormeceu", "Cólica/dor de barriga"), units in metric (ml, kg, cm), decimal comma.
- Tests: a unit test fails when `en` and `pt-BR` catalogs have different key sets or placeholders (including missing plural forms); a lint-level check (`eslint-plugin-i18next` `no-literal-string` in `markup-only` mode, warnings -> errors for new code) or an equivalent test prevents new hard-coded UI strings; render tests for key screens in both locales; the e2e suite runs in English (set the locale explicitly) plus one pt-BR smoke spec.
- PWA manifest: `lang` en; name stays "Lotties" (brand, not translated); `description` may be localized later via a second manifest, out of scope.
- The API's own text is not user-facing except problem `title`/`detail` fallbacks, kept in English.

## 10. Refinement direction (supersedes looser parts of sections 1-5; decided 2026-10-21 after user feedback: "poor design, make it elegant, more icons, very user friendly, helps parents get better every day")
Personality: calm, warm, supportive, confident. Never clinical, never guilt-inducing. One clear thing per screen; progressive disclosure (show only what applies); log anything in two taps; every action is forgiving (Undo).
- Spacing and layout: 4/8 px grid, 20px screen gutters, 16px between cards, 24px between sections; generous whitespace; single column max 480px. Section headers: 15/500 with a small leading icon and an optional trailing text action.
- Surfaces: soft layered dark (subtle top inner highlight `rgba(255,255,255,0.04)`, no heavy borders); cards 20px radius; hairlines only as dividers. Light theme: warm off-white with soft indigo-tinted shadows. Contrast stays AA; avoid pure white text on dark (use `#eceaff`).
- Icons everywhere, one family: `@mui/icons-material` Rounded variants (no new dependency), 24px default, always inside tinted category circles for primary objects (presets, event rows, section headers, empty states), plain 20px inline icons for field labels and segmented options. Every segmented/chip option that represents a thing has an icon (breast, bottle, solid food, left/right, wet/dirty/mixed, nap/night, mood). No emoji.
- Typography: system UI stack with `font-feature-settings: "tnum"` for numbers; hero 32/500, title 20/500, section 15/500, body 15/400, caption 12/400 muted. Never below 12px.
- Motion: gentle 180ms ease-out expand/collapse for conditional fields, sheet slide, pressed-state scale 0.98; reduced-motion respected.
- Empty and first-run states: friendly composed icon illustrations (tinted circles, no external art), one sentence, one action. Skeletons instead of spinners.
- Language of the product: encouraging and factual ("Charlotte slept 11h 40m yesterday, 20 minutes more than her average"). Never judge or alarm; predictions and insights always carry a quiet "estimate, not medical advice".

### Add/edit event sheet (replaces the current form everywhere)
Full-height modal bottom sheet on mobile (dialog on md+), sticky footer. Labels are always OUTSIDE the input (12px medium muted text above the control), never floating/notched, so nothing is ever clipped; inputs are filled (surface-raised), 48px high, 14px radius, helper text only when needed.
1. Header: tinted category icon circle + event type name (20/500) + a quiet subtitle ("Starting now" / "Logged 06:34"); a small chip-style type switcher (tap the name to change type) instead of a big select; close (X) at the left, overflow menu (Delete, in edit mode) at the right.
2. When: row of quick chips `Now · 5 min ago · 15 min ago · 30 min ago · Pick time` (relative labels localized); `Pick time` opens a themed MUI X date-time picker (mobile dialog with clock/calendar styled to the theme; desktop popover); selected time shown as a large pill ("Today, 06:34"). Duration types show Start and End as two time pills with a live computed duration between them ("23 min"), and a `Still running` switch replacing the confusing "leave empty" helper text.
3. Type fields rendered from the definitions with conditional visibility (`visibleWhen`), expanded with a gentle animation:
   - select fields with <= 4 options: segmented chips with icons (never raw option codes: translated labels);
   - number fields: big centred value with − / + steppers and quick-value chips where the field defines them (bottle amount: 60, 90, 120, 150 ml; remembers the last used amount per baby), unit shown as suffix; `inputMode="decimal"`;
   - duration-in-seconds fields (breast left/right) as minutes input with a stopwatch icon ("min") or mm:ss pills;
   - text: single line; notes: collapsed row "Add a note" that expands.
4. Medication: checklist cards with a pill icon, usual medications first, dose inline.
5. Footer: full-width primary pill `Save` (spinner while saving), `Cancel` only as the X; Delete lives in the overflow menu with a confirm.
6. Defaults: smart (method = last used, amount = last used, start = now); validation messages inline under the field, friendly.

## 11. Timeline redesign (user feedback 2026-10-21: "strange filters"; raw codes, ugly chip carousel, every sleep row just says Sleep)
- No duplicate sync UI: drop the "Synced" chip from the Timeline header (the header sync icon is the single indicator; a row shows a small "not synced yet" dot only for pending items).
- Day navigation instead of an endless list with a scrollbar: a date bar `‹  Yesterday, Oct 20  ›` (tap the label to open the themed date picker; "Today" shortcut), swipe left/right changes the day. Each day shows a summary strip: sleep total, feeds, diapers (same cards as Home Today).
- Filters: one `Filter` button (funnel icon, accent badge with the active count) next to the date bar, opening a bottom sheet with checkable category rows (icon + name, multi-select, `Clear` and `Done`). No horizontal chip carousel, no scrollbar. Quick filter chips are allowed only if they fit without scrolling (max 4: All, Sleep, Feeding, Diapers) otherwise omitted.
- Rows: left time column (`06:34`, tabular) with a thin vertical line connecting events and a tinted category dot; right a card with the preset-style title derived from the event: sleep kinds show their own title and icon (`Woke up` sun, `Nap` cloud, `Night waking` eye, `Bedtime` moon, `Fell asleep` zzz), feeding shows `Bottle`/`Breast`/`Solid food` with icon, diapers `Wet/Dirty/Mixed`, medication names, etc. Detail line in muted text built from localized values (`60 ml · Formula`), durations as a pill (`38 min`, running shows an accent `Running` pill with a live timer). Raw codes (`FORMULA`, `woke_up`, `WET`) must never be shown: all option values and kinds go through the i18n catalogs (fallback: humanize the code, Title-case words without underscores).
- Tap = edit (opens the event sheet). Swipe or long-press actions are out of scope. Empty day: friendly empty state with an icon and `Nothing logged this day` + `Add event`.
- Desktop: the column may widen to 640px for the timeline; day bar and rows scale; never a horizontal scrollbar.

## 12. Insights v1 (2026-10-21; owner: "an estimate of how long it will take to get more insights")
Offline-first: everything is worked out on the device from the selected baby's local events (no new API). Code: `code/web/src/insights/` (pure models plus a thin UI); see also docs/design/04-insights-delight.md for the longer-term plan.
- Catalogue (`catalogue.ts`): Sleep (naps and nights; 3 days with data, 3 sessions), Sleep rhythm (7 days, 7 sessions), Feeding (3 days, 6 feeds), Diapers (3 days, 6 changes). A day with data is a distinct local calendar day with at least one relevant event, counted over the last 30 days; imported (Napper) history counts at once because its days are real dates.
- Readiness and estimate (`readiness.ts`): progress = days with data / days needed ("Day 3 of 7", a progressbar). Remaining days are projected at the recent pace: the share of the last 7 calendar days that had data, counted only from the first relevant day (a new logger is not measured against a whole week) and leaving today out until it has data. Pace 0 or no data: "Start logging feeds to unlock"; otherwise "About N more days of logging"; days met but events short: "Log N more feeds to unlock". Friendly, never judgmental, plural keys in en and pt-BR.
- Screen: while nothing is open, the calm "More insights are coming" card lists every insight as a row (category stamp, thin progress bar, estimate). Once one opens: a 7 / 14 / 30-day range switch scoping every card, a card per open insight, the others as compact rows under "On the way", and a quiet footnote "an estimate, not medical advice".
- Cards: serif title, the range averages as serif headline numbers ("13h 03m / day", "6 feeds / day", "391 mL / day", "5 diapers / day") under "Average of the logged days, last N days" (averages use the finished days with data; ml per day uses the days with bottle amounts), the text summary (also the chart's accessible name), optional stat tiles, a legend for two or more items, the chart and a "View as table" toggle with the same numbers (newest day first).
  - Sleep: night and nap columns stacked per local day (a session crossing midnight is split by its instants; pauses excluded through `effectiveMsInWindow`; markers and night wakings are not sleep), average as a reference line.
  - Sleep rhythm: one row per day from 06:00 to 06:00, newest on top; night strong, naps light, wakings as gaps; usual bedtime (bed_time marker, else night start; median measured from noon) and usual wake-up (night end, else woke_up marker).
  - Feeding: feeds per day and bottle milk per day (sum of `amount_ml` of bottle feeds only), each with its average line; average gap (gaps over 8 h left out as unlogged), average bottle, average bottle time (effective).
  - Diapers: changes per day with the average line; wet = WET + MIXED, dirty = DIRTY + MIXED in the summary, tooltip and table.
- Charts: hand-built SVG, no library; chart tokens (`chart.night|nap|feed|diaper`) through CSS variables so light, dark and night follow the scheme; columns at most 24 units with a 4-unit rounded data end, 2-unit surface gap between stacked segments, hairline grid, labels never under 12 px and dropped rather than overlapped; a gentle fade-in that the global reduced-motion and night rules switch off.
- Preview and screenshots: `/dev/insights?state=rich|partial|short|empty`, captured by tests/e2e/design-review/insights-preview.{config,review}.ts (port 5187).
- Formulas card (2026-10-22, docs/design/14-formulas.md): not in the readiness catalogue; it reads the last 30 days (not the range switch). A formula shows with 7 days and 20 bottles naming it; one alone shows its averages as headline numbers, two or more side by side. Order: the "While on Aptamil 2: 0.2 belly pains/day, on Nan 1: 0.4." statements, the plain note right after them ("This compares what you logged. ... Talk to your pediatrician before changing a formula or the amount."), the period of each formula (dates, days, bottles), then per measure one small bar per formula (the `feed` chart token, scaled to the largest value, the number always as text) or "View as table" (measures as rows, formulas as columns); formulas still collecting days are progress rows ("Formula: Nan 1", "Day 4 of 7") inside the card or under "On the way". Never better/worse, causes, should, a target or a threshold. Preview `/dev/formulas?state=insights|single` (tests/e2e/design-review/formulas-preview.*, port 5194).

## 13. Roles in the UI (Caregiver, 2026-10-22; rules in docs/SPEC.md "Roles and permissions")
- One mechanism for every role: `code/web/src/baby/permissions.ts` (`canWrite` Owner|Parent, `canLog` + Caregiver, `canChangeEvent`, `isOwnEvent` from `Baby.userId` or an unsynced `createdBy: null`) and `baby/useEventAccess.ts` (per event: may change, who logged it, `lockedBy`). The server enforces the same rules; the UI only decides what it offers.
- Viewer: unchanged (view-only notice, logging off, rows not openable).
- Caregiver: logs everything (tiles, trays, "+", Day add, own timers). Someone else's entry: the Day row opens a read-only sheet (the ribbon detail's layout: title, time, details, note) with "Added by Ana. Only they or a parent can change it.". Someone else's running timer (owner decision 2026-10-22): Stop, Pause and Resume work everywhere (Day row Stop, Now state card incl. Woke up / Up for the day / Back asleep, timers bar, mini bar, timer sheet); the timer sheet hides its menu, disables Discard and the sleep details and says "Started by Ana. You can pause or stop it; only they or a parent can change the rest."; a stop that needs details opens "Finish this ..." in a restricted mode that only fills the asked, empty fields. Someone else's nursing session stays locked ("Started by Ana. Only they or a parent can change it."), as resuming or switching moves its side clock. Settings shows "You are a caregiver for Lia: ..." and the existing view-only lines of event types, medications, import and members; no "Add prescription" in the Meds tray, no import offer on first run.
- "Given by Ana" under a dose someone else logged (Day row and read-only sheet), for every role.
- Formulas (docs/design/14-formulas.md): a Caregiver picks the baby's formula on a bottle (chips) but has no "+ New formula"; Settings > Formulas is read-only for Caregivers and Viewers ("You can see the formulas but not change them.").
- Role pickers (invite, member role) list each role with its one-line description; the closed field shows the name; the invite picker repeats the description as helper text.
- A change the server refuses for the role is said once in a snackbar (not blocking); see SPEC for what happens to it.

## 14. Appointments (2026-10-22; docs/design/15-appointments.md)
